# DocuWeaver — status
_Updated: 2026-11-06_

## What this is
Django 5.2 web app for aligning multi-page PDF engineering drawings on a Fabric.js canvas and overlaying geo-referenced assets from CSV. Self-hosted, SQLite, single-process. Run with `./start.sh` / `start.bat` (creates venv, installs, migrates, serves) or `python manage.py serve`. Tests: `pytest` (unit/API) and `pytest browser_tests` (headless Chromium; needs `requirements-browser.txt` and `python -m playwright install --only-shell chromium`). Lint: `ruff check .`. User-facing docs live in `README.md`; this file is the development state.

## Architecture map
- `docuweaver/settings.py` — all config from env vars (`env_bool`/`env_list` helpers). Key custom settings: `REQUIRE_LOGIN`, `DATA_DIR`, `DOCUWEAVER_HTTPS`, `DOCUWEAVER_MAX_UPLOAD_MB` (PDF limit), `DOCUWEAVER_MAX_IMPORT_MB`. WhiteNoise for static. `drawings.auth.CsrfCheckWithoutLogin` must stay last in DRF's authentication classes.
- `docuweaver/test_settings.py` — pytest uses this (plain static storage, no manifest needed).
- `docuweaver/urls.py` — login/logout via `django.contrib.auth` views; media served through `login_required_if_enabled(serve)` when DEBUG is off.
- `drawings/auth.py` — `login_required_if_enabled` decorator for page views, and `CsrfCheckWithoutLogin` (CSRF for API requests nobody signed in to). `drawings/permissions.py` — `IsAuthenticatedOrOpenAccess` for DRF. Both read `settings.REQUIRE_LOGIN` at request time so `override_settings` works.
- `drawings/context_processors.py` — exposes `DOCUWEAVER_VERSION` and `REQUIRE_LOGIN` to templates (nav bar).
- `drawings/management/commands/serve.py` — Waitress server; runs `collectstatic` before importing the WSGI app (order matters for WhiteNoise).
- `drawings/api_views.py` (REST API), `drawings/views.py` (pages, plus thin project export/import views), `drawings/services/` (`csv_importer.py`, `pdf_processor.py` which imports `pymupdf as fitz` and has `render_upload`/`PdfError`, `project_archive.py` for `.docuweaver` files, `export_service.py` for the composed PDF and the adjustment report; the PDF's design, including why it uses `garbage=2` and `final=False`, is in `docs/DEV_NOTES.md`, "Composed PDF export"). Save rules (`save_fields`, one owner per imported row) are in `docs/DEV_NOTES.md`, "Project data rules"; upload and CSRF rules in "Uploads and requests".
- `static/js/editor/*.js` — canvas editor modules; load order fixed in `templates/drawings/editor.html`. Architecture notes and conventions in `docs/DEV_NOTES.md`; `verify.js` prints a one-line missing-function check to the browser console on every editor load (`?verify=1` for the full list). Visibility, stacking and dark-mode rules are in `docs/DEV_NOTES.md`, "Display and editing". `static/js/vendor/fabric.min.js` — Fabric 5.3.1 vendored (MIT).
- `browser_tests/` — Playwright browser tests: `conftest.py` starts `manage.py serve` (DEBUG off, sign-in on, temp data dir) and provides the `UI` helper (API calls, exact canvas clicks, failure on console errors/4xx/5xx/error alerts); `drawing.py` generates the known-answer 1:500 drawing and its WGS84/MGA CSVs. Design notes in `docs/DEV_NOTES.md`, "Browser tests".
- `templates/registration/login.html` — login page; logout is a POST form in `templates/base.html` (Django 5 removed GET logout).
- `docker/entrypoint.sh` — migrate, optional first-start superuser from `DOCUWEAVER_ADMIN_USER/_PASSWORD`, then `manage.py serve`.

## Gotchas
- Licence is AGPL because PyMuPDF is AGPL. Replacing PyMuPDF (e.g. with pypdfium2) would be required to relicense more permissively; OCG layer control in `pdf_processor.py` relies on PyMuPDF.
- `DJANGO_SECRET_KEY` is mandatory at import time; pytest gets one via `pytest-env` in `pytest.ini`.
- With `DJANGO_DEBUG=false`, static files need `collectstatic` (manifest storage). `manage.py serve` and the launchers do it; `runserver` with DEBUG off will 500 on the editor page unless you collect first.
- `DOCUWEAVER_HTTPS=true` sets Secure cookies; on plain HTTP nobody can log in. Leave it off for LAN use.
- Hosts other than localhost need both `DJANGO_ALLOWED_HOSTS` and `DJANGO_CSRF_TRUSTED_ORIGINS` (with scheme and port).
- On this dev box `python3 -m venv` lacks ensurepip; use `uv venv --seed .venv` then `uv pip install -r requirements-dev.txt`.
- Releasing: bump `__version__` in `docuweaver/__init__.py` (shown in the nav-bar title tooltip), add a dated `CHANGELOG.md` section, push, wait for CI, then `git tag -a vX.Y.Z -m "DocuWeaver X.Y.Z"` and `gh release create vX.Y.Z --title "DocuWeaver X.Y.Z" --notes-file <changelog section>`.
- Versioning follows SemVer as the CHANGELOG says: a release that adds features or changes settings/API behaviour is a minor bump (that is why the review fixes shipped as 1.1.0, not 1.0.2). Commit as `90254972+NitroghostGH@users.noreply.github.com` (set in `.git/config` and the global config); another address shows up on GitHub as a second contributor.
- `git shortlog` without a revision hangs in non-TTY shells (reads stdin); pass `HEAD`.
- Only SQLite is supported. Its JSON check constraint rejects `NaN`/`Infinity`, which is why migration `0015` only cleans assets (float columns), not links (JSON).
